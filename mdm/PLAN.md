# 학생 기기 통제 및 수업 관리 시스템 (MDM) 기획서

## 1. 프로젝트 개요 (Overview)

본 프로젝트는 교실 및 학교 환경에서 학생들의 디바이스(태블릿, 스마트폰, PC 등)를 실시간으로 모니터링하고 제어하여 수업 집중도를 높이고 최적화된 디지털 학습 환경을 제공하는 **학습 관리 및 MDM(Mobile Device Management) 시스템** 개발을 목표로 합니다.

* **시스템명:** Smart Class Control MDM (가칭)
* **주요 대상:** 초·중·고등학교, 학원, 기타 교육기관 (교사 및 학생)
* **주요 목적:**
  * 수업 중 불필요한 앱 및 웹사이트 차단 (앱/웹 통제)
  * 학생 기기 화면 실시간 모니터링 및 원격 제어
  * 수업 자료 양방향 공유 및 화면 전송
  * 정책 기반의 자동화된 디바이스 상태 관리

---

## 2. 시스템 아키텍처 (System Architecture)

전체 시스템은 **관리자/교사 단말(Controller)**, **학생 단말(Agent)**, 그리고 이를 중계하고 정책을 관리하는 **중앙 백엔드 서버(Server)**로 구성됩니다.

```
[ 교사 단말 (Web/App) ] <---> [ 백엔드 및 실시간 서버 (WebSockets/gRPC) ] <---> [ 학생 단말 (Agent App) ]
                                          |
                                    [ DB / 정책 저장소 ]
```

### 2.1 주요 구성 요소를 위한 기술 스택 (추천)
* **Agent (학생 단말 앱):** Android (Kotlin / Java) 또는 Cross-Platform (Flutter/React Native + Native Plugin)
  * *권한 요구사항:* Device Admin(기기 관리자), Accessibility Service(접근성 서비스), Usage Stats(사용 정보 접근)
* **Controller (교사/관리자 웹):** React / Vue.js / Next.js
* **Backend Server:** Node.js / Go / Java Spring Boot
* **실시간 통신:** WebSocket, WebRTC (실시간 화면 공유/스트리밍)
* **데이터베이스:** PostgreSQL, Redis (실시간 세션 및 정책 캐싱)

## 3. 세부 기능 사양 (Detailed Features)

### 3.1 학생 기기 통제 및 관리 기능 (Core MDM)

1. **앱 사용 제한 (App Lock / Whitelist):**
   * **화이트리스트 방식:** 허용된 교육용 앱만 실행 가능, 그 외 앱은 자동 종료 또는 비활성화.
   * **블랙리스트 방식:** 게임, SNS, 유튜브 등 특정 지정 앱 실행 차단.
2. **웹사이트 차단 (Web Filtering):**
   * 차단 URL 키워드 및 도메인 기반 필터링.
   * 브라우저 실행 시 지정된 학습 사이트 외 접근 차단.
3. **하드웨어 및 시스템 제어:**
   * 카메라, 블루투스, Wi-Fi tethering(핫스팟) 강제 비활성화.
   * 볼륨 제어 및 화면 밝기 고정.
   * 전원 끄기/리부팅 방지 및 설정 앱 접근 제한.
4. **락다운 모드 (Kiosk Mode):**
   * 수업 시작 시 학생 기기를 단일 학습 앱 또는 전용 런처 화면으로 고정.
   * 홈 버튼, 최근 앱 버튼, 상단 알림창 내리기 차단.

---

### 3.2 실시간 수업 관리 및 모니터링 (Classroom Management)

1. **실시간 화면 그리드 뷰 (Live Screen Grid):**
   * 교사 화면에서 연결된 모든 학생들의 화면을 썸네일 형태로 실시간 모니터링.
   * 이상 행위(비허용 앱 시도 등) 감지 시 그리드 상에 경고 표시.
2. **화면 공유 및 전송 (Screen Sharing):**
   * 교사 화면을 전체 학생 기기에 일괄 전송 (전자칠판 대용).
   * 특정 학생의 화면을 다른 학생들과 공유 (발표 모드).
3. **원격 제어 및 지원 (Remote Control):**
   * 조작이 서툰 학생의 기기를 교사가 원격으로 직접 조작하여 제어.
4. **일괄 명령 전송:**
   * 전체 학생 기기 화면 즉시 잠금 ("선생님을 보세요" 모드).
   * 지정된 URL/자료를 전체 학생 기기 브라우저로 동시 오픈.

---

### 3.3 사용자 및 학급 관리 (Administration)

1. **학급 및 출결 관리:**
   * 수업 코드(PIN) 입력 또는 QR 코드 스캔을 통한 간편 접속.
   * 접속 학생 상태(온라인/오프라인/제어 적용 중) 실시간 파악.
2. **정책 시간표 설정:**
   * 교시별(예: 1교시~4교시) 자동 차단 정책 예약 기능.
   * 방과 후 자동 해제 기능 제공.

## 4. 핵심 기술 구현 요약 (Technical Key Points)

### 4.1 Android OS 기준 기기 제어 핵심 API
* **DevicePolicyManager (DPM):**
  * 기기 관리자(Device Admin) 또는 Owner 권한 확보 필요.
  * `setApplicationHidden()`: 특정 앱 숨기기 및 차단.
  * `addUserRestriction()`: 카메라, 핫스팟, SD카드 등 사용 제한.
  * `startLockTask()`: 키오스크 모드(화면 고정) 실행.
* **AccessibilityService (접근성 서비스):**
  * 실행 중인 패키지명을 실시간 감지(`TYPE_WINDOW_STATE_CHANGED`)하여 차단 대상 앱 실행 시 즉시 홈 화면으로 튕겨냄.
* **WebRTC / RTSP:**
  * 화면 프레임을 저지연(Low-latency)으로 교사 단말에 스트리밍 전송.

## 5. 단계별 개발 로드맵 (Development Roadmap)

### Phase 1: MVP (최소 기능 제품) 개발
* 학생 앱: 접근성 권한을 이용한 앱 차단 기능 및 화면 캡처 전송.
* 백엔드: WebSocket 기반의 기본 연결 및 명령(잠금/해제) 처리.
* 교사 웹: 학생 목록 확인 및 단일 화면 락/언락 명령 전송.

### Phase 2: 통제 기능 확장 및 실시간 스트리밍
* 학생 앱: Device Owner 권한 적용, 런처 고정(Kiosk Mode), 웹 URL 차단.
* 교사 웹: WebRTC 기반 멀티 썸네일 실시간 화면 그리드 모니터링.

### Phase 3: 고도화 및 안정화
* 예외 상황 처리 (네트워크 끊김 시 자동 정책 유지).
* 정책 시간표 스케줄링 및 상세 리포트(학생별 딴짓 횟수, 접속 기록 등) 기능 개발.
* 보안 강화를 위한 앱 삭제 방지 및 우회 경로 차단.

---

## 6. 개발 시 유의사항 (Considerations)

1. **권한 승인 문제:**
   * MDM 특성상 Android의 경우 `Device Owner` 권한 설정이 필요할 수 있으며, 이는 ADB 명령을 통한 초기 세팅 또는 Knox/EMM 솔루션 연동이 필요합니다.
2. **네트워크 부하 관리:**
   * 다수의 학생(30~40명)이 동시에 화면을 스트리밍할 경우 로컬 네트워크(AP) 과부하가 발생할 수 있으므로 썸네일 프레임 레이트(FPS) 및 해상도 최적화가 필수적입니다.
3. **학생들의 우회 시도 대비:**
   * 안전모드 부팅, 앱 강제 종료, 팝업 창을 통한 우회 방지 로직을 구현해야 합니다.
